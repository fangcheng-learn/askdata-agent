# 目标进度与缺口分析（goal_analysis）

## 适用与运行方式

回答明确经营目标“已完成多少、还差多少”，按需给所需节奏或有条件的达成情景。简单进度查询证据充分即可回答；只在用户要求且数据支持时延伸到达成分析，不强制完整诊断、预测或报告。

该 Skill 提供业务方法，供当前 ReAct 主体按需加载和取证，不预排固定计划、不选入口路由、不派生子 Agent。实际调度、权限、预算、修复、澄清恢复和最终审核由 Controller／调用方协议处理。变化原因可按需使用经营诊断方法，不自动扩展用户目标，不执行投放、补货等经营动作。

## 必要资料与缺失处理

- 完整问题、已有确认条件；目标值、单位、指标、周期、范围、来源及版本。目标来自用户明确提供或合法配置，不能把历史最好值、广告预算或模型建议当经营目标。当前公开快照没有独立目标表时不得造目标。
- 绑定数据源和快照、真实当前时间、业务时区、观察截点、交易覆盖、单位和能力边界。快照场景日期只是元信息；相对时间统一使用机器真实当前日期／时刻解释。
- 已登记指标与依赖、事件时间、成熟度及重复风险；相关表字段、粒度和关联。已有适用语义复用，缺什么补什么，不凭名称重定义指标。
- 真实结果及 ID、来源 SQL／查询口径、范围、期间、完整性与检查状态。预测或未来情景另需可观察历史、经营安排和明确参数。

目标或关键口径缺失时询问会改变答案的条件；可先报告已核实实际，但不能声称完成率已算出。“最近”未指明长度且无可继承期间时先问；已有期间不重复询问。普通补查不逐次征求确认。语义未提供、尚未查询或执行失败分别记录，不能因此宣称数据不存在。

## 对齐目标与实际

核对目标来源、版本、指标、完整周期、店铺／SKU／渠道范围、币种及税、运费、退款口径。相对周期先按真实今天解析为绝对边界，后续同任务及恢复时保持；数据仍只来自唯一授权快照。

请求期间超出数据覆盖时说明具体缺口，不能自动退回快照月份、把无覆盖当零、换截面补未来或把部分月实际当整月实际。目标与实际无法对齐时先澄清或只报告可比部分，不能擅自换指标或缩放目标。尾窗中的售后更新不代表仍有新交易。

## 核实进度与计算依据

1. 获取期间内可观察的完整实际聚合；按事件时间和信息可得时间核对范围。支付、发货、退款完成、退货验收不能统一按订单创建日归期，后续退款不回写支付 GMV。
2. 对可累加、越高越好的目标，目标为 T、实际为 A：完成率 A/T，有符号差额 T−A；可另列剩余缺口 max(T−A, 0) 和超额。T≤0 时不套完成率公式。
3. 比率、成本上限或越低越好的目标按已确认方向比较；百分点、金额和数量各用正确单位，不套“剩余日均销售”公式。比率使用同集合分子分母，不能平均子组比率。
4. 证据保存目标原文／配置引用、指标定义、完整结果 ID、覆盖与计算链。关联先按事实粒度聚合或去重；截断、Top N 或样本不能用于总体进度。查询成功不认证业务口径，发现问题只修受影响部分。

## 用户要求时再分析达成条件

- 先核对目标周期剩余可经营时间、历史可比性、观察成熟度和供给／预算约束。可累加目标的“剩余缺口÷剩余可经营天数”是所需节奏，不是预测；没有剩余时间时不除零。
- 情景需列方法、公式、参考窗口、参数来源、假设和区间。“已实现值＋假定日均×剩余天数”只是在该假设下的值，不产生无依据的达成概率或承诺。
- 将缺口换算为增量订单、每单金额或转化时，必须有适用的公开公式和同口径参数。买家不能替代订单，日买家累加不能充当期间去重人数；相互依赖的情景增量不能相加，广告归因收入不能当广告增量。
- 未来经营安排、需求／供给参数或完整历史不足时，保留已知进度和条件式要求；不因缺预测条件否定事实查询，也不强扩复杂预测。

## 充分性、下一动作和交付

进度问题在目标可追溯、实际可比、覆盖与完整性明确、计算可复核时即充分。达成／弥补问题还需关键经营时间、方法、参数和约束可追溯；条件式答案可以充分，不要求确定预测。

仅当仍有影响原问题的必要缺口、存在可执行取证且预算允许时建议补查／修复；缺用户能提供的参数时请求澄清，继承任务与剩余预算。确实受限时分别说明已回答部分、未查询项、执行／完整性问题、口径问题及确实不支持的能力；不直接用 partial 替代可执行的补查。

不调用逐步过程审核。运行层生成草稿后独立最终审核一次，必要且有实质证据／草稿变化时才再审。预算和最终状态由 Controller 维护，不因新增建议重置。

输出包括目标及来源、实际与观察范围、完成率／差额、关键结果 ID、口径和覆盖；涉及未来时另列所需节奏、情景假设、约束及待确认条件。用户需要时再展开报告。

## 经营与查询分工

经营 ReAct 根据真实证据提出 query_batch 业务取数要求（指标、比较、维度、必要输出及已有结果引用），不生成 SQL 或查询契约。固定 SQL 模块自动复用并补齐相关 Schema、登记口径、样例和关联，逐项取数及受限技术修复；不替经营主体决定下钻方向。Skill 只规定业务方法，不要求经营主体先选择物理字段。资料未取得和数据源确实不支持必须区分。每批计一轮业务取证，技术准备不占轮，实际工具和时间共享预算。

## 问题与证据的持续核对

用户描述保持为待核实线索，不能当成查询事实或推断用户心理。按稳定问题ID维护影响核心答案的待答／受阻项和相关竞争解释，保存支持、反证、范围及证据版本；技术失败不等于问题已回答。报告展示相关指标的正常、异常和抵消变化及未决边界。可选延伸不必穷尽，核心必要缺口有可行路径且预算允许时继续。SQL生成次数以调用方统一账本为准，新任务总共3次（首次＋2次修复）；计算严格按实际工具Schema，不忽略未知参数或将自比较当跨期变化。
