# 目标进度与缺口分析 Skill（goal_analysis）

应用级业务 Skill，由 Harness 按需注入。回答“已完成多少、还差多少”，按需进一步分析“能否达成、怎样弥补”；简单进度问题直接核验并回答，不强制生成计划或报告。

## 适用与不适用

- 适用：有明确经营目标的完成率、剩余缺口、所需节奏及有条件的达成情景分析。
- 不适用：替用户制定未经确认的目标、承诺达成、自动调整广告或补货等业务操作。实际变化的原因调查可建议交由经营诊断继续，不必为进度查询扩展完整诊断。

## 必要输入与缺失处理

运行层需实际提供以下内容；Markdown 路径或引用不代表已加载：

- 完整问题、相关已确认条件；目标值及单位、指标口径、目标周期、业务范围、来源与版本。目标仅来自用户明确提供或后续合法配置；当前公开数据没有独立经营目标表，不能把历史最好值、广告预算或模型建议当目标。
- 当前绑定的数据源与快照标识、场景日期、时区、观察截点及比较规则、业务覆盖范围、单位和能力边界；来自该快照的 `dataset_metadata.json`、`capabilities.json`。
- 同快照 `metrics.json` 的指标、依赖、事件时间、成熟度及重复计算风险，`schema.json` 的相关表字段、粒度和关系，`glossary.json` 的相关歧义条目。
- 可用查询工具及相关真实结果：结果 ID、来源 SQL/查询契约、时间与范围、行数、完整或截断标记；已有结果只有满足当前口径和完整性才复用。需要预测时，另需可观察历史、未来经营安排及明确的情景参数。

目标缺失或关键口径不一致时询问会改变答案的业务条件；可先提供已确认口径下的实际值，但不能声称已算出完成率。普通补查和细分不逐次征求确认。语义或绑定信息缺失时，建议运行层补充；“尚未查询/结果未提供”不等于“必要数据不存在”。只有公开能力、字段或覆盖已确认不支持时，才说明数据缺失。

## 最小分析与证据

1. **对齐目标和实际。** 核验来源、目标版本、指标、周期边界、店铺/SKU/渠道范围、币种、税/运费/退款口径。只用绑定快照及匹配结果，不混入另一快照的信息；将“本月”等按其场景日期解释，不用机器日期，列明目标完整周期和实际已观察区间。
   - 证据：目标原文或配置引用、指标定义、快照元信息及范围映射。
   - 改向：目标与实际无法对齐时先澄清或仅回答可比部分；不能擅自换指标、缩放目标或把部分月实际当整月实际。尾窗末快照不代表交易延续至快照当月，须检查实际经营覆盖，不能把无交易覆盖当正常经营的零销售。
2. **核实实际并计算进度。** 按公开指标及依赖获取期内截至截点的实际值。检查事件时间、可知时间、关联粒度、去重、金额对账和结果完整性；查询成功不代表业务口径正确，截断结果不能当全集。
   - 证据：可追溯的聚合结果及契约、必要对账、完整性说明。支付、发货、退款完成和退货验收分别入期，不能统一按订单创建日；后续退款不回写历史支付 GMV。
   - 对“越高越好”的可累加金额或数量目标，设目标为 T、实际为 A：完成率 A/T、有符号差额 T−A；可另列剩余缺口 max(T−A, 0) 和超额部分。T≤0 时不套完成率公式。比率、成本上限或反向目标按已确认方向比较，差异使用百分点等正确单位，不套“剩余日均销售”公式。
   - 改向：发现重复联结、范围不一致或截断时建议修复/补查，不用有问题的数继续推演。若用户只问当前进度，证据充分即可结束。
3. **按需分析达成条件。** 用户要求预测或弥补方案，才检查目标周期剩余可经营时间、历史可比性、数据成熟度和供给/预算等约束。对可累加目标，可计算“剩余缺口÷剩余可经营天数”的所需日均；这是要求的节奏，不是预测。没有剩余时间时不除零，报告周期已结束或等待到期事实成熟。
   - 证据：剩余经营安排、历史序列及窗口、样本覆盖、约束参数。预测须列出方法、公式、训练/参考窗口、假设和情景区间；例如“实际值＋假定日均×剩余经营天数”仅为该假设下的情景值，不给无依据的达成概率。
   - 改向：缺未来经营安排、需求/供给参数或完整历史时，仅给已知进度、条件式要求和缺口，不输出确定达成判断。尾窗中的售后更新不能作为新增需求趋势；广告归因、转化及退款指标须处理同 cohort、观察窗和成熟度。
4. **按证据提出弥补选项。** 将缺口换算为所需增量订单、客单或转化等，仅在公开公式适用、参数来源明确且可比时进行。注明约束与重叠，不能把相互依赖的情景增量相加，不能把归因收入当广告增量。
   - 证据：计算链、参数来源、可观察能力与约束；区分已验证事实、假设和待验证措施。证据不足时输出待确认条件；可建议继续、补查、调整计划或结束，不执行经营动作。

## 回答充分与部分回答

- **进度已充分：** 目标可追溯且与实际可比，实际覆盖和完整性明确，完成率/差额计算可复核；无需额外证明未来一定达成。
- **达成或弥补分析已充分：** 在上述基础上，方法、可经营时间、关键参数、约束和情景假设可追溯，结论强度与证据相称。充分可以是明确的条件式答案，不要求确定预测。
- **只能部分回答：** 目标未确认、实际口径无法对齐、覆盖/成熟度不足、结果未取全或关键未来参数缺失。明确已回答哪部分、尚未查询什么、数据不支持什么，以及哪项补充会改变判断；不把未观察到的未来事实填零。

## 输出

按问题规模给简短文字或小表：目标及来源、实际值和观察范围、完成率/差额、快照场景日期与口径、关键结果引用。涉及未来时另列所需节奏、情景方法与假设、约束及待确认参数；明确事实与推演的区别、限制和未解决问题。只有用户需要时才展开报告。

本 Skill 仅定义业务判断与下一步建议；实际调度、语义和结果注入、状态保存、权限校验及重试限制由 Harness 实现，不假定已有控制接口。

## 简短示例

- 用户：“本月成功支付商品 GMV 目标 5 万欧元，全店，还差多少？”核对场景月、目标币种单位和支付商品口径，查询截至截点实际，给完成率、缺口及来源；无需自动预测。
- 用户：“按刚才的目标，月底能完成吗，差额怎么补？”先核对剩余经营安排和可比历史；参数足够时给所需日均与明确假设的情景，参数不足时报告当前缺口及待确认条件，不承诺达成。
