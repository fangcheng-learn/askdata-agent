# 只读数据查询（database_query）

## 职责与输入

根据本次查询目标、真实字段级 Schema图、指标语义和已确认条件生成只读 DuckDB SQL，通过当前用户可用的 MCP 数据库工具执行。不能绕过工具、权限或绑定快照。不承担整个调查的路由、完整计划或最终报告。

输入可能是简单查数，也可能是 ReAct 中的一次查询动作。持续区分任务原文与当前查询目标：任务原文保留用户意图，本次 SQL 只完成当前目标，并继承明确的对象、期间、比较基准、口径及真实结果依赖。不能把整个多步问题挤进一条 SQL，也不能丢掉任务条件。

使用调用方实际提供的字段图、登记指标、已确认参数、可用工具和结构化结果。Schema 已取得且适用时复用；需要新字段／指标／关系就提出具体缺口，不猜名称、不扫描其他库或仓库。路径、结果编号或字段标签本身不代表已读到数据。

## 时间与覆盖

- 所有数据源的相对时间以机器真实当前日期／时刻为参考，按明确业务时区解析。快照场景日期不代替今天。调用方已有明确绝对边界时复用，不重复调用时间工具；尚未解析且可用时间工具时按工具协议取得边界。
- “最近”没有长度且无可继承期间时请求澄清，不默认7天或本月至今；比较基准或业务对象缺失且会实质改变答案时才询问。完整的新问题不能只当成旧澄清选项。
- 已确定期间在同任务后续和恢复时保持，不每步按今天重新滚动。明确改期时由调用方使受影响证据失效。
- 仅查询绑定授权快照，核对公开覆盖和观察截点。请求日期超出覆盖时说明，不能把无记录当零、自动改查快照月份、暗中缩短期间或换另一截面补未来。

## SQL 与多查询边界

1. 单次数据库执行只含一条只读 SELECT／WITH 语句；合法 CTE、子查询、UNION、窗口和条件聚合可以使用。不得写入、建表、调用外部文件／网络或探查未授权来源。末尾分号不表示需要另一条语句。
2. 同一任务允许多次查询；ReAct 调用方允许时，同一轮可提出多个彼此独立的查询。每条分别有目标、SQL、必要契约、结果和错误，分别计数。需要上一结果才能确定对象、参数或方向时等待真实结果，不能填造中间数值。不要用分号把独立 SQL 拼成一段执行。
3. 同来源、同集合和期间的相关指标可合理合并聚合；不同总体、粒度或口径不能为追求一条 SQL 而强行关联。真实依赖明确引用已取得结果和版本，不能从聊天摘要猜数。
4. 只用已提供且授权的真实表字段、字段类型和关联。使用表的 name、字段的 sql_name，内部 id 用于引用；不能把输出别名或 CTE 列误当物理表字段。DuckDB CSV 视图使用物理表名，不加数据库或 schema 前缀。
5. 明确输出列；原始表不使用 SELECT *。简单 CTE／子查询的已知星号可由程序展开，不要求模型为等价展开重写。不得自行调用 DESCRIBE、PRAGMA 或 information_schema 探查结构。
6. 优先完整聚合。工具预览200行不等于全集；完整结果按授权引用读取，超保存上限仍可能不完整。不能为了显示擅自加 LIMIT。用户要求 Top N 时明确范围；需要总体贡献时另外保留总体和“其他”依据。
7. 查询列名唯一、清楚，中文或技术别名均可，别名不改变业务定义。金额单位和币种来自元数据；件数不能冒充金额，买家数不能冒充订单数。平均值和比率须说明实际分子分母及统计集合。

## 简明查询契约与检查

本Skill由SQL模块自动提供。执行协议4以调用方实际query_protocol.output_schema为唯一输出定义；成功项为query_id、status=query、sql、metric_declarations和可选local_measurements、technical_note。每个query_id只完成一个绑定目标，首生成可有多个独立项，修复仅失败子集，不追加最终报告。

metric_declarations声明指标名称、真实物理source_fields、aggregation及必要的派生definition。登记口径由程序绑定，不抄写整份定义。tables、dimensions、filters、time_range、time_ranges、grain等机械结构由程序按实际SQL提取，保留派生表达式和多个物理来源；协议4不再另写query_contract。SQL已有月份输出别名时保留SQL表达式即可，不把别名当作物理字段。

旧调用方按query_protocol.query_contract_schema声明query_contract.metrics，仍可省略机械字段；协议4使用output_schema，不套用旧字段。显式声明不能与SQL或用户范围冲突，程序不能替模型猜业务定义。统一使用包含起点、排除终点的范围，完整自然月结束于下月一日。DATE的<=末日可与<次日等价，TIMESTAMP的<=末日零点不能代表末日全天。

权限、只读、快照、真实字段及可以证明的来源／单位／聚合／筛选／时间冲突须处理。合法CTE、UNION、窗口、条件聚合和派生维度不能仅因有限匹配未识别而判错；暂不能证明的语义保留validation.pending_checks供后续分析和最终审核。SQL成功或basic_valid并不证明完整业务正确。

## 业务澄清与技术准备

先利用当前Schema、真实样例、登记口径和候选映射解决字段及关联问题。missing_requests只是待解析线索；如果当前上下文已经提供字段，就应映射后查询，而不是要求用户确认物理字段。实体名称须映射实际键，不能把“A店”等用户显示名称直接写成store_id；不能把未绑定名称造成的空结果当业务事实。

需要用户明确的只有会影响答案的业务参数、指标定义或实体身份。例如“按品类会话转化”需知道登记分母是落地还是浏览该品类的会话，不能只使用下单商品把未购买会话排除。真正的业务澄清用status=clarify及category=business_parameter|metric_definition|entity_identity；选项结构以调用方真实Schema为准。

技术资料、物理字段或关联缺口用status=missing_context，不把内部字段选择推给用户；确认数据能力无法支持时才unsupported。缺口响应不同时附SQL。未登记但可用公开资料定义的量，在local_measurements中说明id、definition、scope、实际来源和统计集合／单位，不冒充已登记指标。

普通单项的旧call_tool／clarify及显式step_protocol继续按调用方协议兼容：最小query_contract只需metrics业务声明；工具权限和step_decision均由实际Schema控制，不在Skill里维护第二份格式。新调查不需要独立Planner、额外判定模型或过程Reviewer。

## 度量说明和受限修复

### 流量、状态和累计台账

先区分期间发生量与时点状态。订单／支付金额可按事件期间筛选；库存、账户余额、预占、在途等累计台账不能先截取报告期间再从零累计。先用当前授权快照内的完整必要历史重建期初状态，或明确计算期初余额再叠加期间变化；下界筛选必须放在状态重建之后。已授权的历史不等于未来，重建仍必须服从观察截点和信息可得时间。

状态分区键按实际业务粒度（例如SKU×仓库），按事件时间和稳定次序键排序。相同时间多事件不能任意排序；累计与LEAD应使用一致顺序，累计窗口明确ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW。不能把不同仓库或账户的独立状态误混成一个序列。

时长按真实状态区间与报告期间求交集：开始取较晚值、结束取较早值，区间跨日／跨月时按实际交集分摊到各日／月，不把整段时长全归开始月。保留进入报告期间前最后一个有效状态，末段延伸只到报告期末或授权观察截点；负时长不计，未知初值不默认零。库存可售需按登记定义扣预占，在途不能代替已入库；无货访问／库存阻断事件可作独立核对，但不能冒充精确失单。

同一SKU平均成交金额变化仍可能来自折扣、购买时间／订单构成。要解释调价或促销结束，应核对公开价格／折扣事实的生效区间，按事件时点关联；不能只用成交均价上涨宣称标价上调。比例的统计集合须在输出说明中保留，例如品类落地会话与浏览过品类的会话不同，即使使用同名基础指标也不能省略这个范围。

本轮measurement说明与已登记语义明确统计对象、计数键、单位、事件时间、统计集合及必要筛选；真实来源与返回列按同一说明绑定。不能用购买会话替代支付订单，也不能将同是某个月的不同事件集合强行合为一个统计量。未登记但可由公开资料构造的量须明确任务内定义，不自动冒充正式指标。不同集合可分量聚合或按后端绑定项分别查询，不自行增加query_id。

修复逐项读取原始错误和结构化诊断中的出错指标、实际表达式、期望对象／时间及合法来源，实质修正冲突，不只改空格或别名。新任务每条逻辑查询总共最多3次生成（首次＋2次修复），旧任务以调用方实际账本为准。成功项保留，换ID、改名或拆分不能清零。服务、权限、资料、参数或存储问题不应一概要求重写SQL。


### 完整台账的状态时长
对于由增减台账重建的状态时长，优先复用 `calculate/state_duration`，不要每次自行重写累计窗口与跨期切分。先由SQL模块取得所选分区（如SKU×仓库）的原始完整历史：保留唯一期初记录、时间、稳定事件序号、全部正负变动及期初标记，只按分区对象筛选，不按目标月份、状态或变动正负裁剪，不做分组、抽样或LIMIT。对象筛选可用子查询，或按分区键与已登记唯一键维表连接；连接不能复制事件或按事件时间、变动状态截断历史。保留原始计算列，等价的简单CTE包装可用。结果完整性和权限仍由既有结果引用机制校验。SQL模块可在同一query项附postprocess=state_duration；Controller自动保存原始R并执行算子，无需主Agent再重查或重规划。传入真实列、按已登记定义的delta_terms（例如可售量是on_hand_delta减reserved_delta）、期初标记、比较期间及时区。算子按真实顺序累计并求各期间交集，来源截止由服务端提供，模型不能延长。一次操作可计算多个分区和期间；不会占新取数轮，但计入工具和时间预算。

分组筛选不能改变登记指标的统计集合。访问/浏览转化的分母不能通过INNER JOIN或EXISTS订单、支付记录来限定为已下单/已支付会话；那属于下单后的支付率。商品/品类的浏览集合应从对应浏览事件构造并去重，入口集合使用入口维度，按请求明确区分。若使用新的条件集合，返回任务内指标的真实定义，不冒充原登记访问或转化指标。
结果包括期初/期末状态、每分区持续小时与连续区间数。连续区间数不等于变动记录条数，持续时间不等于受阻订单数；跨SKU或仓库相加属于对象小时，不能直接与单个月日历小时比较来排除原因。证明损失大小或因果机制仍需相应业务证据；无需求加权或阻断证据时不得把时长直接转换成损失或断言影响可以忽略。若缺少完整期初或可靠观测边界，明确缺口，不能补零。
