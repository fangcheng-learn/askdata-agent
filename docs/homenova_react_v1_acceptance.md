# ReAct V1：实施前固定验收范围

日期：2026-10-29。用户已授权依框架调整方案开发和测试。本文件在新增真实任务前固定；失败不缩小范围，不覆盖旧验收台账。

后续政策说明：本文件保留三次真实运行前固定的标准及当时token限制，不改写原失败依据。用户随后确定Token仅观察、普通ReAct最多5轮、每SQL总共最多生成2次；后续代码和本地回归以[最新次数预算报告](homenova_react_iteration_budget_report.md)为准，本次无新增真实任务。

## 顺序和调用上限

1. 先执行公开语义下的手写 SQL 探针，经查询契约、只读／权限、编译及真实本地 MCP 执行；对关键聚合独立读取公开 CSV 核对。错误修复先在此层完成，不消耗付费 Agent 调用。
2. 完成本地控制回归、原功能回归、E 适配和前端检查／构建。受控模型仅验证分支，不能算业务验收。
3. 最多三个不同起点的真实 Agent 任务，各一次；每次预留台账后才调用。不得重新跑同题来凑通过，传输失败或超时也占该次名额。Agent 内有限修复遵循原共享预算并记录，不从头开新任务绕过。
4. 全过程保存至新的 `data/homenova_harness_v1/private/react_v1_20261029/`，包括问题、请求范围、行动、SQL、检查、真实结果引用、Skill读取／实际注入、每次模型用量与耗时、最终审核及停止原因。

## 三个真实任务起点

| 场景 | 问题形式 | 关键判定 |
|---|---|---|
| 全盘变化调查 | 指定可查期间，问 GMV 为什么下降，附少量口语信息 | 先核实当前范围核心指标，依实际数据选择方向；不预设商户或SKU路线；若前提被推翻，如实完成适用问题 |
| 已定位对象 | 指定真实店铺／品类／SKU及期间，问为何变化严重 | 继承该对象，先看内部相关指标；不无目的重做全局排名；所有数字来自授权真实结果 |
| 看板已有发现／假设 | 用户口述看板发现，或携带实际取得的同会话结果后追问 | 标明信息来源；已取得且适用的证据复用，口述线索须核实；允许否定假设，不能把用户判断直接当原因 |

自然问题不描述调查步骤、不指定SQL或预置答案。实体和期间由公开数据能力确定，题目在调用前记账；不使用私有参考答案编写运行提示词。HomeNova只有一个店铺时如实保留此限制，不为多店场景造数。相对时间统一机器今天；“最近”无期间则澄清，快照覆盖不足不当零。本轮正常业务题使用明确历史期间，避免把时间覆盖失败充作调查验证。

## 固定通过标准

- 继续覆盖原八类控制验收：简单查数、正常调查、前提不成立、缺参数／能力不足、单步修复、预算停止、多轮追问、最终交付。
- Flash只做路由／目标理解，不选Skill；调查无Planner和过程Reviewer。ReAct同次调用更新进度并选择动作，独立SQL批次各自执行／计数，依赖实际结果。
- Schema／口径默认继承、缺口补查，按稳定ID去重；每轮只携带相关材料，不能漏掉必要定义、真实数值或完整性状态。
- Skill同时更新来源稿和实际应用副本。提示词明确职责、工具动作、证据强度、必要取证、边界停止和异常反馈，不能只有一句泛泛要求。
- SQL正例覆盖聚合、分组、多指标、CTE、别名、去重、CASE/FILTER、日期包含性等；负例保持越权、跨快照、写入、明确错误口径与时间冲突的拦截。
- HTTP200、SQL成功和completed均不单独判业务通过。总体及贡献数字须独立核算；区分贡献、关联和原因，不把买家计数当订单或月去重人数。
- 草稿后正常最终审核一次，展示定稿不再自由改写。必要可行缺口且预算允许才继续；没有实质变化不得重复送审。部分完成必须说明具体缺口，预算未审明确标注。
- SQLite持久保存任务／结果；重启按原引用授权读取及原任务继续，预算和已确定期间不重置；中断调用不自动重放。
- 费用控制初值：Chat累计160,000 token、检索模型累计80,000 token、单次输入门槛48,000、最大输出4,096、调查收尾预留60,000。前两题运行时按UTF-8保守上界准入，该单次计量方式已由下方修订记录取代；失败依据、结果及消耗保留。当前单次准入使用本地Qwen基础BPE加25%余量和消息开销，累计预占仍按UTF-8上界加最大输出，返回以API usage结算。数值未上调，这是用量边界而非人民币金额上限。
- 所有模型请求都在发起前预占、返回后按usage结算；缺失usage和失败调用保留保守计量。输入估算不是精确分词，报告区分估算与实计。记录各输入区块大小，完整用量日志不得倒灌模型。

本文件固定标准不代表已完成验收。真实结果及未完成事项写入 `docs/homenova_react_v1_report.md`；旧报告、原始快照、生成器与答案不修改。

## 实施修订记录：单次输入计量修正

前两题已真实运行各一次，均在SQL前被单次输入检查停止（UTF-8保守上界55,195、48,125，对应初值48,000）。真实已发生的Chat输入分别11,216、10,100；被阻止的下一调用没有供应商输入用量，不得把字节上界称作其真实token数。原失败、输出和额度占用保持，不重跑、不改判通过。

第三题前修正计量职责：单次48,000输入限制使用本地Qwen官方基础BPE估算并加25%安全余量及消息开销；闭源qwen3.7的准确计费仍以API usage为准。任务累计预占继续用更保守的UTF-8字节上界加最大输出，成功后按usage结算，未知用量不按零释放。Chat160,000、检索80,000、收尾预留60,000、最大输出4,096、工具20次和300秒均未上调。

本次是输入估算与累计费用预占的分层修正，不减少业务通过要求，不新增名额。两次查询前失败仍计失败；仅做本地离线检查与受控回归后，使用最后一个不同场景验证。词表资产在开发时从官方仓库取得、保留许可与SHA，运行期不联网取词表，也不调用付费Token计算API。
