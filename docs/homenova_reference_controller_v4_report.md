## 本次实现

修改对象仍为`references/askdata_studio`，不删除业务功能，不关闭权限检查，不增加模型节点或过程审核。修复前固定的检查范围见[本轮验收条件](../scripts/homenova_harness_v1/reference_controller_v4_acceptance.md)。

1. **统一结果引用。** 新增共享解析入口，步骤建议、数值比较、分析输出和最终审核都使用同一规则。在当前用户、任务、快照与有效依赖范围内，逻辑证据ID和旧result_ref唯一对应同一结果时，规范为逻辑ID并记录修改；未知、歧义、失效、不完整和跨范围引用仍拒绝，不进行全局查找。只规范化模型实际选择的证据，不把全部输入自动认作判断依据。
2. **模型只看到一个证据编号。** 后续查询、步骤分析、草稿及审核的输入隐藏内部存储引用，程序侧仍保留原读取引用和审计记录。业务结果中碰巧叫result_ref的数据列不删除，原模型输出也不改写。
3. **保护既有复用。** 已授权历史结果复用时，创建当前任务的新逻辑证据与读取引用，保留来源记录；旧引用不能因此越过原用户／任务限制。
4. **停止无效修复。** 内层no_progress会传到外层，同一输入不再次生成。同一计划或上游有实质更新、显式失效后才允许重新执行，原预算不重置。判断下游可否修复时先检查所有上游，修复额度已耗尽或不可恢复的上游不会触发下游空转；有路径时修最上游必要根，保留独立有效结果。
5. **接受真正的部分交付。** 最终审核已给出有证据、有边界的内容，而剩余失败／阻塞步骤没有可执行修复路径时，直接接受partial；不把Reviewer的complete当整项任务完成，也不再生成同一阻塞下的草稿。实质修改或新证据必要时仍能再审，空白与编号变化不会重复审核。

额外发现：原S2 SQL在两个已明确列出字段的中间结果上使用`SELECT *`，编号修复后会遇到下一道误拦。程序现在只对明确、唯一的单CTE／子查询输出进行等价展开，记录原候选与实际执行SQL。原始表星号、未知／重名列、递归、EXCLUDE／REPLACE，以及可能改变USING／NATURAL合并列含义的未限定JOIN星号不自动放行；真实表权限仍按作用域检查。
