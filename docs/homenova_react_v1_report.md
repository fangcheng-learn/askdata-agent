### 第三题关键查询与数字

真正执行的只读SQL产生证据 `8a6202684aeb:R1`，按月份、渠道计排除内部流量后的不同会话ID：

```sql
SELECT date_trunc('month', s.started_at) AS month_start,
       s.source_channel, COUNT(DISTINCT s.session_id) AS session_count
FROM sessions s
WHERE s.is_internal_traffic = false
  AND s.started_at >= '2026-06-01T00:00:00+02:00'
  AND s.started_at <  '2026-08-01T00:00:00+02:00'
GROUP BY date_trunc('month', s.started_at), s.source_channel
ORDER BY month_start, session_count DESC;
```

10行全部与独立CSV核算一致：会话24,932→24,704，减少228（-0.9145%）；自然搜索+346，直接访问-75，通用付费搜索-209，社交付费-178，品牌付费搜索-112。

但月去重可观察 `visitor_id` 是23,158→23,083（-0.3239%），并非上述会话指标，也不等于可靠识别的自然人数。两月分别30天和31天，日均会话下降4.1108%。原回答不能据会话数确认看板的“访客”口径。渠道差额只说明下降贡献；公开快照已有广告相关能力，本次未查，不能说数据源缺乏，更不能据此认定原因调查完成。[独立核算](../data/homenova_harness_v1/private/react_v1_20261029/case3_independent_review.json)

## 错误、修复和部分交付

1. **新增预算估算误停。** 前两题将55,195和48,125的UTF-8字节保守上界，直接拿去和48,000的单次token门槛比较；不是SQL契约失败，也不是供应商欠费。修正为单次本地Qwen基础BPE加25%余量及协议开销；累计额度仍用字节上界加最大输出预占、API usage结算。所有数值限额不变。第三题真实通过了该准入，但前两题未重跑。
2. **查询契约生成不合规。** 第三题首次把时间只写在filters而time_range=null，第二次把month别名填成物理维度，均在真正SQL前拒绝，第三次才执行。原SQL本身的执行能力不等于契约填写合规。本轮补强提示词，明确期间、物理维度、正式指标ID；没有绕过校验。该提示词补强仅本地检查。
3. **计算接口不明确与重复失败。** 模型把日期行值当成base_field/current_field，三次失败。现明确四种计算的参数、真实列名与宽表要求；错误返回可用列和修复路径，失败前登记实际依赖；同逻辑动作共享修复次数，相同参数失败不重复执行，成功结果可复用。新增10项受控测试通过，未再真实调用。
4. **收尾丢失权威定义。** 契约将显示指标规范化成物理字段后，只按名称筛选的上下文漏掉已取得的sessions_count定义。现按实际计量来源保留相关已检索定义，不把这种相关性当作口径认证。专项测试及保存检查点的离线重组通过，权威“不是用户”定义恢复。
5. **最终审核误放行。** 原审核把贡献当充分原因，unanswered为空、can_repair=false，完成状态缺乏依据。现要求结构化完成核对，明确区分计数对象、未查与不支持、贡献与原因。Controller处理完成标签与其缺口／修复要求的确定矛盾；仍错误的审核稿不展示。新调用缺失完成核对或字段类型不合规时不认证交付，旧保存记录仍可读取。已无预算且仍有核心缺口时partial；真正答完或前提被推翻仍可完成。**模型仍可能错误地把检查都填为满足，不能宣称根治语义误判。**

真实第三题触发的是**额外修复预算停止**，不是20工具／300秒／累计token耗尽；它保留了已取得的真实结果并做一次收尾审核，但原完成标记错误。修复后的partial、无变化不重复审核、必要缺口回取证和未审核状态均有受控验证，**没有新增真实partial案例**。
