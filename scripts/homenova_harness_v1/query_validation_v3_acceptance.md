# 查询校验简化：实施前固定检查范围

用户于2026-10-28授权：减少措辞与命名阻断，兼容常见等价表达；保留权限、只读、快照及明确业务冲突检查。不增加过程Reviewer或模型节点。原两次付费试运行名额已用完，本轮新增付费模型／Agent任务为0。

1. `<>`与`!=`、可识别的运算符大小写规范化；已识别注册指标／单物理计量的定义由程序补齐，缺少definition或措辞不同不触发模型重试，原值和修改记录保留。
2. 显示名称不决定真实口径。原始计量按真实来源建立规范名称与描述；合法中文／技术别名及多期输出均可通过。未知业务名称不能被程序认证为新指标。
3. 未重复声明的SQL筛选、复杂去重计数等价写法记录为待核对项及实际SQL摘要，允许受控执行，不将结构检查通过标为业务正确。
4. GMV用quantity、错误来源、明确SUM／AVG冲突、声明时间／筛选未落实、越权／写操作／跨快照仍被拦截；已有日期时区等价、权限及结果读取测试保留。
5. 待核对项跟随原query_contract进入真实结果、下游步骤与最终审核。带有未解决计算／筛选疑问的证据不能被用于跳过调查分支；不新增复杂结果状态机。
6. 使用保存的GMV候选离线回放：确认规范化及去重语法不再误拦，可执行时仅由本地只读DuckDB执行，并与独立公开CSV核算比较。利润题原候选的GMV／quantity冲突应被识别，不强行执行来凑通过。
7. 内外修复共享原预算；相同错误与相关产物均未变化时停止重复修复。改变契约而SQL未变可以是有效进展。
8. 完成本地后端、E适配及前端构建；保护文件指纹、两次付费台账及旧运行文件不变。没有真实模型复验就明确标注未验证。

上述是固定检查条件，不因实际失败缩小范围。开发资料不进入运行时Skill、提示词或检索源。
