## 审核调用调度专项标准（2026-10-28修订，实现和验证分别记账）

以下标准替代原“关键节点／异常触发过程审核、合并末尾审核”及“由Controller解释任意Planner业务条件”的验收设计。Executor前置判断、代码校验和独立大模型审核分别记录；不把过程Reviewer改名搬入Executor，也不增加一次判断模型调用。

| 场景 | 通过标准 |
|---|---|
| S1、S2、S3等正常中间步骤 | 独立大模型过程审核调用均为0，不在每步后额外调用Reviewer决定是否继续 |
| 每步代码校验 | SQL执行状态、查询契约、输入输出字段、已注册指标口径及时间／单位／聚合约束、结果完整性和步骤依赖均有可追溯校验记录；不能静默跳过失败项 |
| 上游数据传递 | S2明确依赖S1时读取R1的必要结构化数据、来源、时间和口径，不只收到成功标记或聊天摘要 |
| 前提核实、本步适用性和步骤选择 | Planner声明前置／不适用条件及影响范围；Executor在原有单步调用中读结果并提出动作，Controller校验后结合实际状态和预算调度；不要求通用规则解释器 |
| 本步适用且继续执行 | 同次Executor模型调用返回查询动作、SQL及契约或分析动作；不得拆为“先模型判断、再模型生成SQL”两次调用 |
| 命中不适用／终止条件 | 同次调用返回动作、前提状态、条件ID、真实证据、受影响要求／步骤、剩余目标和简短理由；不继续扩展该步调查或生成该步SQL，不要求暴露或控制模型内部思考 |
| GMV没有下降且仅有下降归因任务 | Controller复核后只跳过相关归因，生成含两期数字、变化及纠正说明的草稿，经最终审核正常完成；不自动partial，不直接结束请求 |
| GMV没有下降但有独立目标 | 继续明确的独立目标；模型返回空剩余清单时，Controller仍与服务端完整要求核对，不能漏做 |
| 比较期／口径不一致、数据缺失或不完整 | 状态为尚不能判断，修复、补查或必要澄清；不能把无法比较当作没有下降，也不擅自变更口径寻找局部下降 |
| 结构化建议的代码约束 | 条件及证据引用真实合法，影响范围在任务内，明确数值计算复核；越权、失效引用和跨范围跳过被拦截，模型建议不直接决定终态 |
| 代码可直接判断的硬约束 | 权限、预算、上游执行失败和依赖不可用由代码即时处理，不等待下一步模型发现；不产生无意义Executor调用 |
| 最后一步返回新结果 | 代码检查后交已有草稿生成和最终Reviewer承接，不额外增加一次末步过程审核 |
| 空结果、证据矛盾、执行／依赖错误 | 使用现有代码分支与受控状态处理，异常触发的大模型过程审核调用为0 |
| Executor不能确认本步适用性或证据含义 | 明确尚不能判断、未决问题及所需证据，建议补查、澄清或重规划，由Controller受控处理；不擅自收尾，也不临时增加过程Reviewer |
| 正常计划任务完成并满足代码交付条件 | 先生成报告草稿，再调用独立Reviewer最终审核1次；保留证据、口径、完整性和回答边界检查 |
| 最终审核建议complete或partial，但仍有必要可执行步骤 | Controller返回执行，不直接以partial结束；关联实际缺口、步骤和预算，不依赖审核文字自行宣称预算耗尽 |
| 最终审核发现遗漏比较期或必要调查 | 原步骤可修复则定向修复，原计划遗漏则按额度重规划；同任务继承条件、结果和预算，不重走入口 |
| 修复／补查产生实质性新证据并更新草稿 | 记录变化、上次问题及再次审核必要性，必要时再次最终审核；仍共享原任务预算 |
| 针对审核问题实质修改草稿 | 必要时重新审核修改后的草稿；同一次Reviewer直接给出的已审核定稿可展示，无需追加审核 |
| 草稿、证据与口径无实质变化 | 首次审核后新增Reviewer调用为0；不反复发送相同草稿争取放行 |
| 仅更换ID、版本号、时间戳、排序或排版 | 不视为实质变化，不触发再次审核 |
| 修复额度／任务预算耗尽 | 停止相应工作，独立可执行工作仍按规则处理；有边界交付须经最终审核，未完成审核则明确标注，不展示未审核草稿 |
| 历史问题已解决或仅局部步骤受阻 | 最终状态依据当前有效缺口与阻塞推导；历史stop_reason不能永久否决完成或挡住其他独立步骤 |
| 日志和界面 | 分开展示上游结果、Executor前置建议、条件、前提状态、影响范围、剩余目标、代码校验、Controller动作及最终审核；再次审核有实质变化依据，独立过程Reviewer计数为0 |

Executor的前置判断仅限本步及Planner声明的条件，不逐步重审整个任务的正确性、完整性或因果强度。判断后不再查询仍会消耗那次已有模型调用，验收不能将其记为零成本；独立过程Reviewer调用必须为0，前置判断不新增模型调用层。

必要的查询生成、步骤分析及Planner重规划不等于审核调用；其原有预算约束不变，也不得用这些名称变相恢复过程Reviewer。预算保持工具20次、单步额外修复2次、重规划1次、主动300秒／调查240秒、前端等待360秒，内外重试共享额度，等待用户时暂停主动计时。

这些是固定判定标准；本地控制验证与真实业务验证分开，未覆盖项不能算通过。旧运行记录和旧测试不能作为新审核策略已经通过的证据。最新逐项边界见`docs/homenova_harness_v1_implementation_v2_report.md`。
